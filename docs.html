1. Arquitectura del proyecto

El proyecto se construye sobre Bagisto 2.x, una plataforma e-commerce open-source basada en Laravel 12 + Vue 3 + Tailwind con arquitectura modular orientada a paquetes. Cada módulo (Catalog, Customer, Checkout & Sales, Shop, Admin) vive en packages/Webkul/* como un paquete Laravel autónomo.

2. Entorno de desarrollo (Docker Compose)

El archivo docker-compose.yml orquesta los servicios: aplicación Laravel, MySQL, Redis, Elasticsearch, Kibana y Mailpit. 

# Levantar el entorno completo
docker compose up -d

# Instalar dependencias e inicializar Bagisto (primera vez)
composer install
cp .env.example .env
php artisan key:generate
php artisan bagisto:install

La tienda queda disponible en http://localhost y el backoffice en http://localhost/admin.

3. Pipeline CI/CD

Integración Continua (GitHub Actions)

El workflow .github/workflows/ci.yml se dispara en cada push y pull_request a las ramas 2.4 y main, y ejecuta:

  1. Laravel Pint — análisis de estilo del código del equipo (falla el pipeline si hay violaciones).
  2. PHPStan (larastan) — análisis estático nivel 5 configurado en phpstan.neon.
  3. Pest — suite de regresión Product Unit Test definida en phpunit.xml.
# Ejecutar los mismos checks localmente
./vendor/bin/pint --test packages/Webkul/Product/src/Helpers packages/Webkul/Product/tests
./vendor/bin/phpstan analyse --no-progress
./vendor/bin/pest --testsuite="Product Unit Test"

Despliegue Continuo a Azure

El workflow .github/workflows/deploy.yml despliega automáticamente a la VM de Azure al integrar cambios en la rama 2.4: hace git pull, instala dependencias, limpia cachés y ajusta permisos.

HU-04 · Backoffice

4. Exportación del catálogo a CSV

Permite a los administradores descargar el catálogo completo de productos en CSV con un clic, usando streaming por bloques de 500 filas para soportar catálogos grandes sin agotar memoria.

Archivos involucrados

  • packages/Webkul/Admin/src/Http/Controllers/Catalog/ProductCatalogExportController.php (nuevo)
  • packages/Webkul/Admin/src/Routes/catalog-routes.php — ruta admin.catalog.products.export_catalog
  • packages/Webkul/Admin/src/Resources/views/catalog/products/index.blade.php — botón "Exportar catálogo (CSV)"

Columnas exportadas

ID · SKU · Nombre · Tipo · Estado · Precio · Stock · Familia de atributos · Categorías · URL Key · Canal · Creado

Cómo probar

  1. Ingresar al backoffice /admin y navegar a Catálogo → Productos.
  2. Hacer clic en "Exportar catálogo (CSV)".
  3. Se descarga catalogo-productos-AAAA-MM-DD-HHMMSS.csv con BOM UTF-8 (compatible con Excel).
HU-05 · Storefront

5. Filtrado por múltiples atributos con chips

El storefront permite combinar filtros de varios atributos (color, talla, marca, precio…) simultáneamente. La mejora del equipo agrega una barra de filtros activos con chips removibles individualmente y botón "Borrar todo", sincronizada con los query params de la URL.

Archivos involucrados

  • packages/Webkul/Shop/src/Resources/views/categories/filters.blade.php — chips + lógica Vue (appliedChips, removeChip, registerOptions)

Configuración previa

Para que un atributo aparezca como filtro: en el admin ir a Catálogo → Atributos → (editar atributo) y activar "Usar en navegación por capas" (filterable). Luego asignar el atributo a la familia de atributos y reindexar si se usa Elasticsearch.

Cómo probar

  1. Abrir una categoría en la tienda.
  2. Marcar opciones de 2 o más atributos (p.ej. Color: Red + Size: M) y un rango de precio.
  3. Verificar que aparecen chips como Color: Red × y que al quitar un chip la lista se actualiza sin recargar.
HU-11 · Storefront

6. Badge dinámico "-X% OFF"

Las tarjetas de producto (vista grid y lista) muestran un badge con el porcentaje de descuento calculado dinámicamente a partir del precio regular vs. precio final que resuelve el motor de precios de Bagisto (special price, reglas de catálogo, etc.).

Reglas de negocio

  • Umbral mínimo del 5%: descuentos menores no muestran badge (se conserva el badge "Sale").
  • Redondeo al entero más cercano, con tope de 100%.
  • Precios inválidos (0, negativos o invertidos) no generan badge.
  • Accesibilidad WCAG 2.1 AA: fondo #B91C1C sobre texto blanco (contraste 5.9:1) y aria-label descriptivo.

Archivos involucrados

  • packages/Webkul/Product/src/Helpers/DiscountBadge.php (nuevo, lógica pura y testeable)
  • packages/Webkul/Shop/src/Http/Resources/ProductResource.php — expone discount_percentage en la API
  • packages/Webkul/Shop/src/Resources/views/components/products/card.blade.php — render del badge en grid y lista

Cómo probar

  1. En el admin, editar un producto y asignar un Special Price (p.ej. precio 100 → special 75).
  2. Limpiar caché: php artisan cache:clear.
  3. Abrir la categoría del producto en la tienda: la tarjeta muestra -25% OFF.
  4. Probar el umbral: special price 97 (3%) → no aparece badge.
HU-09 · Storefront

7. Accesibilidad WCAG 2.1 AA

  • Skip link traducible ("Saltar al contenido principal") hacia #main.
  • Foco visible: outline de 2px en enlaces, botones, inputs y elementos con tabindex (:focus-visible).
  • Etiquetas ARIA: aria-label en badges de descuento, chips de filtros y botones de acción.
  • Contraste AA en el badge de descuento (5.9:1).

Archivos involucrados

  • packages/Webkul/Shop/src/Resources/views/components/layouts/index.blade.php
  • packages/Webkul/Shop/src/Resources/assets/css/app.css
Tras modificar CSS/Blade del tema, recompilar los assets: cd packages/Webkul/Shop && npm install && npm run build

9. Aseguramiento de la calidad

La suite de regresión valida que el cálculo del badge de descuento y la exportación del catálogo no afecten la lógica de precios ni la persistencia.

  • packages/Webkul/Product/tests/Unit/DiscountBadgeTest.php — 8 pruebas Pest / 21 aserciones (casos borde: umbral, redondeo, precios inválidos, arreglo de precios de Bagisto).
  • Testsuite Product Unit Test registrada en phpunit.xml y ejecutada en CI.
